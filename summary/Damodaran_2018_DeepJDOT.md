## 1. 論文の目的または目標は何ですか？

### 背景：ドメイン適応の課題

コンピュータビジョンにおいて、あるドメイン（ソース）で学習したモデルを、異なるデータ分布を持つ別のドメイン（ターゲット）に適用しようとすると、精度が大幅に低下する。これはドメインシフトと呼ばれる問題であり、照明・背景・撮影条件などの違いが原因となる。

本論文が対象とするのは**教師なしドメイン適応（UDA）**：

```
ソースドメイン：ラベルあり
ターゲットドメイン：ラベルなし（学習時）
→ ソースの知識をターゲットに転移させたい
```

### 先行研究JDOTの2つの問題点

本論文はCourty et al.（2017）が提案したJDOT（Joint Distribution Optimal Transport）を出発点とし、その2つの問題を解決することを目標とする：

| 問題 | 内容 |
|---|---|
| **スケーラビリティ** | γがn₁×n₂行列となり大規模データに適用不可 |
| **入力空間での比較** | 生の画像ピクセルでOTを計算するため意味的な類似度を捉えられない |

### 本論文の目標

これら2つの問題をCNNで解決する**DeepJDOT**を提案する：

1. ミニバッチによる確率的近似でスケーラビリティを解決
2. CNNの深い層の特徴空間でOTを解くことで意味的な対応を実現
3. 特徴整合とラベル整合を**同時に**最適化することでクラスを意識したドメイン適応を実現

## 2. トピックを探求するために使用された方法またはアプローチは何ですか？

### 2.1 モデル構成

DeepJDOTは2つのモジュールから構成される：

```
入力画像 x
    ↓ g：特徴抽出器（CNN）
潜在表現 z = g(x)  ← ここでOTを計算
    ↓ f：分類器（MLP + Softmax）
クラス確率 f(g(x))
```

gとfはソース・ターゲット両ドメインで共有される（Figure 1参照）。

![Figure 1: DeepJDOT overview](<../image/ Damodaran_2018_fig1.png>)

### 2.2 目的関数（数式6）

$$\min_{\gamma, f, g} \underbrace{\frac{1}{n_s}\sum_i L_s(y^s_i, f(g(x^s_i)))}_{\text{①ソース分類損失}} + \sum_{i,j} \gamma_{ij} \left[ \underbrace{\alpha\|g(x^s_i) - g(x^t_j)\|^2}_{\text{②特徴整合}} + \underbrace{\lambda_t L_t(y^s_i, f(g(x^t_j)))}_{\text{③ラベル整合}} \right]$$

| 項 | 役割 |
|---|---|
| ① ソース分類損失 | ソースドメインの分類精度を保つ（破滅的忘却を防ぐ） |
| ② 特徴整合 | γで対応づけられたペアの特徴ベクトルを近づける |
| ③ ラベル整合 | γで対応づけられたペアをソースの真ラベルで分類できるようにする |

①がないとターゲット適応に偏りすぎて**破滅的忘却**が起きるため、ソース損失の追加が重要。

### 2.3 交互最適化アルゴリズム（Algorithm 1）

γ・f・gを一度に最適化するのは困難なため、交互最適化を行う：

**ステップ1：γの更新（f, gを固定）**

$$\min_{\gamma \in \Pi(\mu_s, \mu_t)} \sum_{i,j} \gamma_{ij} \left[ \alpha\|\hat{g}(x^s_i) - \hat{g}(x^t_j)\|^2 + \lambda_t L_t(y^s_i, \hat{f}(\hat{g}(x^t_j))) \right]$$

- f, gが固定されるとコスト行列Cᵢⱼが定数になり、純粋な線形計画問題になる
- **network simplex flow アルゴリズム**で効率的に解く
- ターゲットの疑似ラベル f(g(xᵗ)) をコスト計算に使用

**ステップ2：f, gの更新（γを固定）**

$$\min_{f, g} \frac{1}{m}\sum_i L_s(y^s_i, f(g(x^s_i))) + \sum_{i,j} \hat{\gamma}_{ij} \left[ \alpha\|g(x^s_i) - g(x^t_j)\|^2 + \lambda_t L_t(y^s_i, f(g(x^t_j))) \right]$$

- γが固定されると通常の深層学習の最適化問題になる
- 誤差逆伝播で解く
- ソースの**真ラベル** yˢᵢ を使用（疑似ラベルではない）

### 2.4 疑似ラベルとソース真ラベルの使い分け

```
γの更新：疑似ラベル f(g(xᵗⱼ)) を使用
  → 「今のfが犬と予測するターゲットは犬のソースと対応させる」

f, gの更新：ソースの真ラベル yˢᵢ を使用
  → 「γが対応づけたペアに対してソースの真ラベルで学習する」
```

この使い分けにより、疑似ラベルへの直接的な過学習を防いでいる。

### 2.5 ミニバッチによる近似（数式7）

大規模データへの対応として、バッチサイズmのミニバッチでOTを近似：

```
フルデータ：γはn₁×n₂（例：60,000×60,000 = 36億要素）→ 不可能
ミニバッチ：γはm×m（例：500×500 = 25万要素）→ 扱える
```

ミニバッチOTは真のOT結合には収束しないが、近傍サンプル間で質量を共有する**正則化効果**として機能する。

|---|---|---|---|---|
| 数字認識 | スクラッチCNN | 各500 | 0.001 | 0.0001 |
| Office-Home | 事前学習済みVGG-16 | 記載なし | 記載なし | 記載なし |

## 4. 結論は何であり、なぜそれが重要なのですか？

### 4.1 結論

DeepJDOTは以下の3点を同時に実現した：

1. **スケーラビリティの解決**：ミニバッチOTにより大規模データへの適用が可能
2. **意味的な特徴整合**：CNNの深い層でOTを解くことで意味的に適切な対応を学習
3. **クラスを意識したドメイン適応**：特徴整合とラベル整合の同時最適化

### 4.2 なぜ重要か

**理論的意義：**

```
JDOTのコストを最小化する
= ドメイン適応の学習誤差上界を最小化する
= ターゲットでの誤差を減らすことに理論的根拠がある
```

**実用的意義：**

```
・画像生成（GAN）などの複雑な手法を使わず
  シンプルな損失関数の設計だけで
  最高水準の性能を達成

・CNNアーキテクチャを選ばず汎用的に適用可能
  （数字認識：スクラッチCNN
    Office-Home：VGG-16
    VisDA：ResNet-50）

・テスト時はfとgだけで予測可能
  → γは学習時の一時的な道具であり
    推論コストは通常のCNNと同じ
```

### 4.3 今後の課題（論文より）

- マルチドメインシナリオへの拡張
- 複数の埋め込み層にわたる類似度を考慮したより複雑なコスト関数の検討
- 異なる分類器にわたるラベルの類似度の活用

## 5. その他

### 5.1 最適輸送（OT）の基礎

OTは2つの確率分布を最小コストで変換する輸送計画γを求める問題：

$$\text{OT}_c(\mu_1, \mu_2) = \min_{\gamma \in \Pi(\mu_1, \mu_2)} \langle \gamma, C \rangle_F = \min_{\gamma} \sum_{i,j} \gamma_{ij} C_{ij}$$

- **γ**：ソース×ターゲットの対応行列（行和・列和が各分布に一致）
- **C**：コスト行列（ペア間の距離）
- **柔らかい対応**：ハードな1対1割り当てではなく質量を分割して複数サンプルに対応可能

### 5.2 JDOTからDeepJDOTへの発展

| 手法 | 特徴空間 | スケール | ラベル考慮 |
|---|---|---|---|
| 通常のOT | 入力空間 | 全データ | なし |
| JDOT | 入力空間 | 全データ | あり |
| StochJDOT | 入力空間 | ミニバッチ | あり |
| **DeepJDOT** | **CNN深層特徴** | **ミニバッチ** | **あり** |

### 5.3 ハイパーパラメータの解釈

数字認識タスクでの設定（α=0.001, λt=0.0001）：

```
α : λt = 10 : 1
→ 特徴整合をラベル整合より10倍重視

ただしOffice-Home・VisDAの値は論文に記載なし
タスクや損失関数のスケールによって最適値が変わるため要調整
```
